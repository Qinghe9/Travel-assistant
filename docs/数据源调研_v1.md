|---|---|---|---|

| C2 | ChinaTravel-Sandbox（英文表） | 同上行数，与中文表双语对齐 | CC BY 4.0 |

价值：

1. 七大类别与流程文档 7.4 的 `category` 枚举（attraction / food / transport / hotel / tips）几乎一一对应，可直接落成 chunk 元数据。
2. 每个城市都有景点 + 餐厅 + 酒店 + 地铁站，天然满足「按城市过滤」（FR-02 / AC-003）的测试数据需求。
3. 铁路 5,345 条、航班 720 条可当作工具层 mock，让火车/航班分支在没有签约供应商 API 的情况下也能联调与演示（PRD 第 7 章把铁路/航班列为需正式供应商，课程期间无法取得，此为合规替代）。
4. 与本来源同源的查询集（D1）共享同一套实体 ID，评测时不用手工对齐。

使用边界：这是**沙箱数据**，发布方明确其为基准评测用途，且历史上修正过字段细节错误（官方 Discussion #2/#3 与 DATA_QUALITY_REPAIRS_2026_08）。因此**只用于结构化检索、过滤、评测与工具层联调，不作为「营业时间/票价」等事实性答案的唯一依据**；这类事实必须走工具证据（tool_call_id）。

## 3 魔搭（ModelScope）专项检索（2026-10-11 实测）

检索方式：平台搜索接口 `/api/v1/dolphin/datasets`，75 个关键词（旅游／旅行／景点／酒店／民宿／美食／菜谱／铁路／航班／POI／地图／地址／地理／天气／知识图谱／携程／点评……），去重后 294 条，再对 34 个高相关候选逐条核验 README 与仓库结构，并抽样下载真实数据确认格式。

**一句话结论：魔搭上没有「中国景点攻略正文」这类可以直接当主语料的库；真正有价值的是三样东西——全国 POI 点位、中文地址要素标注、天气实况回放。** 这三样恰好补上了第一轮调研里最缺的口子。

### 3.2 魔搭上最容易踩的三个许可坑（实测）

1. **搜索页的许可字段不可信，必须以仓库 README 的 front-matter 为准。** 实例：`iic/GeoGLUE` 搜索页标 Apache License 2.0，README 实际写 CC BY-NC 4.0。
2. **数据堂（`DatatangBeijing/*`）全系列**：搜索页统一标 Apache License 2.0，但 README 明确写「版权归数据堂所有，商用数据」。已用 `20846_Groups_Image_Caption_Data_of_Cookbook` 逐条验证。**直接排除**。
3. **携程／大众点评／同程／下厨房的爬虫小数据集**：魔搭上至少 12 个（`aeufdane/xiechenghotel`、`qiuqiuDL/ctrip_hotel_comment_liangzhu`、`Dylquira/abcd`、`xiyouhxy/hupaocommentsfromtongcheng`、`wzbmy18`、`drngxfw`、`wulutingbai/xcf`、`wuxiansanjin/web-scraper`……），全部 2026-07 的课程作业，几十 KB 到 1 MB，README 自述「八爪鱼采集器爬取携程用户评论」。**PRD 6.1 已明确不把这类结果写入仓库**，且单店 200–1000 条毫无语料规模——只能当字段设计参考。其中 `wuxiansanjin/web-scraper` 下载量 10 万+，容易被误当成优质数据，务必注意。

## 4 许可登记要点

1. **CC BY-SA 4.0（维基导游）**：署名 + 相同方式共享。NOTICE 需写明来源 URL、快照日期、许可原文链接；对外分发派生语料时需同源许可。
2. **ODbL 1.0（OSM）**：数据库层面的署名义务，衍生数据库需同源。只把 OSM 用于检索、不对外分发衍生库时风险较低，但仍需署名。
3. **CC BY 4.0（GeoNames / Open-Meteo / ChinaTravel）**：署名即可，最省事，建议作为首选。
4. **CC0（Wikidata）**：无义务，但本机 SPARQL 不可达，暂不作为首批来源。
5. **OpenKG 中国旅游景点知识图谱**：页面标注 CC BY，但自述「抽取自百度百科和互动百科」（2017 年），上层许可存疑。**建议只用于地名/别名/坐标对齐，不引入其正文描述**；评审严格时直接弃用，用 B1–B4 + Overpass 替代。
6. **许可分层与「私有知识」口径**：PRD 6.4 把「许可公开语料」也算进私有知识，但流程文档 7.4 与要求按 `source_type`（private / public）分开登记并分别报告命中率。实操建议：
   - `public`：A1、A2、B1–B4、C1、C2；
   - `private`：以 C1/C2 的实体为骨架，**人工校订并补写**的景点/美食/贴士条目（目标不少于文档总数的 30%），以及本地运维知识（营业时间口径、预约规则、避坑提示）。
   - 理由：任务书评分表要求「生成回答 100% 基于私有知识」，若语料全部是 CC 公开语料，答辩时「自有数据」一项无证据可交。
