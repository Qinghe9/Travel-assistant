# T34–T36 偏好隐式化、天气覆盖与 POI 治理

## 提示词原文

> 删除长期偏好在答案开头的固定播报；修复“敦煌3天行程”只返回两天天气；
> 过滤餐饮结果中的美甲店等生活服务类 POI；合并鸣沙山月牙泉的重复景区；
> 县级空气质量回退到地级时，必须明确标注不是本地监测点。

## AI 原始输出

- 每轮答案固定以“已结合你之前的长期偏好：离景点近、靠近景点……”开头；
- 敦煌曾只返回 `10-26`、`10-27` 两天；
- 鸣沙山月牙泉以普通名称和“风景名胜区”后缀出现两次；
- 婺源餐饮结果混入“茉里美甲美睫”；
- ShowAPI 对敦煌返回酒泉数据，正文虽有解释，但工具证据头部缺少统一标注。

## 根因

1. 偏好已经通过 `profile_hint()` 进入 compose 提示词，正文播报属于重复仪式；
2. 偏好存储只按字符串直接去重，“离景点近/靠近景点”“亲子/带娃”未归一；
3. LLM 可能在用户未明确日期时把“3天”猜成明天开始，旧逻辑又用今天计算结束日，
   形成 N−1 天窗口；
4. 高德同一景区可能以名称变体返回多次，餐饮类型码也可能混入错误分类；
5. ShowAPI 空气质量只覆盖到部分行政层级，返回的地级区域未形成结构化说明。

## 修改

- compose 保留 `_destination_source_notice`，删除偏好正文播报；
- compose trace 新增 `preference_hint` 与归一后的 `profile_preferences`；
- `store.py` 增加偏好别名归一，读取旧 profile 时也清洗；
- 新增连续 N 天日期锚定函数，用户明确日期优先，否则从今天或已确认起点计算；
- 高德餐饮增加生活服务黑名单；
- 景点结果按名称前缀关系或 500 米距离合并，保留信息更完整项；
- 行程装配新增同景区跨时段合并，避免“上午景点 + 下午同景区继续”重复计数；
- ShowAPI 县级回退时输出“XX（YY上级行政区，非本地监测点）”并注入 compose 约束；
- 新增偏好、天气 2/3/7 天、餐饮过滤、POI 合并、空气回退测试。
